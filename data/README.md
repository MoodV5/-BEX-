掲載方針の確認日：2026年10月18日。

納入実績・取引先メーカー・スクリーン詳細・図面資料は全て掲載し、スクリーンの製造・販売と「Visual Master」を引き継ぐ方針です。
[全体の更新手順](../docs/MAINTENANCE.md)と[引き継ぎ確認票](../docs/HANDOVER.md)も参照してください。
過去の調査メモはGitに含めないローカル資料のため、新しい担当者は前任者から安全に引き継いでください。メモがない場合も、この手順から管理できます。

## 編集する場所

- `reference-content.json`：納入先101件、設備説明136件、メーカー34件、スクリーン4シリーズ・44仕様。元ページ・資料のURLも記録しています。
- `site-pages.json`：全公開ページのファイル名・表示内容・生成対象かどうか。公開ファイルを集める処理でも使います。
- `../scripts/build-reference-pages.mjs`：ページ構成・説明文・表の表示方法。
- `../vm1.html`：スクリーン一覧と、生成ページの共通ヘッダー・フッター等の基準。
- `../reference.css`：実績・メーカー・図面ページのスタイル。
- `../downloads/visual-master/`：PDF44点、DXFのZIP44点。シリーズ別に保存しています。
- `../images/screens/`：旧サイトから引き継いだBE・BA・BS・BLの製品画像。

## ページの生成

プロジェクトのルートで次を実行します。Node.js標準機能のみを使い、追加パッケージは不要です。

```sh
npm run generate
```

次の6ページを生成し、全HTMLのヘッダー・フッターを `partials/` の共通部品に揃えます。画像・CSS・JavaScriptの更新番号とサイトマップも同期します。

- `concept_3.html`：納入実績
- `concept_4.html`：取引先メーカー
- `vm2.html`：BE ケース入り電動スクリーン
- `vm3.html`：BA 天板式電動スクリーン
- `vm4.html`：BS ケース入り手動スクリーン
- `vm5.html`：BL 天板式手動スクリーン

生成したHTMLを直接編集すると再生成時に置き換わります。更新はJSONデータか生成スクリプトに反映してください。生成済みの印がない同名のHTMLは、保護のため上書きしません。

その後 `npm run check` で確認してください。生成結果の一致検査は読み取り専用で、勝手にファイルを直しません。

## JSONを編集するとき

JSONは文章や一覧を構造化したファイルです。項目名は変更せず、値を修正します。文字列は半角の二重引用符 `"` で囲み、項目の区切りに半角カンマを使います。最後の項目の後ろに余分なカンマを入れないでください。

| JSONの項目 | 変更する情報 |
| --- | --- |
| `customers` の `name` / `systems` | 納入先の名称 / 設備の説明 |
| `makers` | 取引先・メーカー名の一覧 |
| `screenSeries` の `name` / `description` / `features` | シリーズ名 / 説明 / 特長 |
| `screenSeries` の `variants` | 型番・サイズ・画面比率・図面の対応 |
| 図面の `path` | このプロジェクト内の実際のPDF/ZIPの場所 |
| 図面の `source` | 元資料の出典URL。変更履歴を追うために残す |
| `sourceDate` | 元情報を確認した日。単に生成した日ではない |

仕様を推測して埋めないでください。図面や型番の追加・削除は参照データと関連検査にも影響するため、経験者と一緒に実施します。特に現在の安全検査は公開図面88ファイルの維持を確認しており、正式に資料数を変更する場合は `scripts/check-security-config.mjs` の期待数も根拠を残して見直します。

## 情報の扱い

- 納入先名・メーカー名は元の掲載順・表記を引き継ぎ、名称が納入・取引当時のものを含む旨を表示しています。現在の社名への自動置換や、現在も取引中との一律の断定は行っていません。
- 納入当時の設備内容は実績として掲載し、販売終了した個別製品の現行商品としての紹介とは区別します。
- 図面は原本のまま保存しています。寸法・仕様の変更が必要な場合は承認された原本に差し替えてください。生成スクリプトは図面の内容を変更しません。
- ページ表示や資料ダウンロードにはビルドサーバーやPHPは不要です。HTML・CSS・画像・資料を公開サーバーへ配置して使います。
- 資料の入手元と公開先の対応はJSON内の `source` と `path` で追跡できます。旧資料URLの転送設定にも利用できます。
