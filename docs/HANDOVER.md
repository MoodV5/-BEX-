# 引き継ぎ確認票

[最初のページに戻る](../README.md)

新しい担当者が、公開の可否や連絡先を推測せずに作業するための確認票です。
パスワードを書き込まず、保管先と権限の確認だけを行ってください。

## 1. まず前任者・先方に確認する

| 確認すること | 記録欄（秘密情報は記入しない） |
| --- | --- |
| 掲載内容を承認する人 | 未記入：担当者に確認 |
| サーバー作業を承認する人 | 未記入：担当者に確認 |
| サーバーの保守窓口 | ATWインターネットサービス。契約書・管理台帳の最新連絡先を確認 |
| GitHubリポジトリの所有者・閲覧権限 | 未確認：組織・担当者と確認 |
| 現在の公開版の日時・Gitコミット | 未記入：本番と照合して記録 |
| 公開前バックアップの保管先・復旧担当 | 未記入：本番作業前に確認 |
| 管理画面・転送・メール認証情報の安全な保管先 | 未記入：承認されたパスワード管理方法で共有 |
| 問い合わせの受信・返信を担当する人 | 未記入：先方に確認 |
| 障害時の連絡方法・対応時間 | 未記入：先方に確認 |
| 月次点検・更新を担当する人 | 未記入：先方に確認 |

## 2. このプロジェクトで決まっていること

- 想定する公開URL：`https://www.bex.co.jp/`。
- 問い合わせの受信先：`soumu@bex.co.jp`。SMTPの送信元・認証アカウント：`uto@bex.co.jp`。訪問者のメールアドレスは返信先に設定する。
- 問い合わせ受付時間：平日9:00～18:00（土日祝日を除く）。
- 防災は掲載する。採用・ドローンは今回の移行対象にしない。タイルカーペットは販売品目に含めない。
- スクリーンの製造・販売と「Visual Master」を引き継ぐ。納入実績・メーカー・スクリーン詳細・図面を掲載する。
- サービス提供範囲は先方と確認済みの方針を維持する。旧サイトにないという理由だけで削除しない。
- 画像は実際の社内・施工写真ではなくイメージを含む。実績写真と誤認させない。
- ホームの文字アニメーションはサイト内から戻る際に繰り返さず、再読み込み時には再生する。下層ページには文字の浮上アニメーションを付けない。カードのホバー効果は維持する。

今後方針が変わった場合は、変更日・承認者・変更内容を作業記録に残してから反映してください。

## 3. 決定済みと混同してはいけない「未確認事項」

- 本番へ今回のファイルが配置されたか、どの版が公開されているか。
- 本番のPHPバージョン。以前の提供画面は7.4.33だったが、現在値は管理者に確認する。
- Apache/nginxでアクセス制限と保護ヘッダーが有効か。
- 本番SMTPの認証・送信・受信箱への到達。ローカルのダミーSMTPテスト成功とは別。
- iPhone実機・Safariでの最終表示確認。
- 具体的な現行製品仕様、スクリーン図面の最新版、デモ条件など、公開直前の掲載承認。
- プライバシーポリシーの文言が実際の個人情報の運用と一致しているか。
- 既存WordPressを今後どう扱うか。今回のHTMLファイルを作っただけでは更新・停止されない。

## 4. 引き継ぎ完了チェック

- [ ] 原本の保管場所とGitHubの権限を確認した。
- [ ] `README.md` を読み、ローカルで `npm run check` と `npm run preview` を実行できた。
- [ ] 生成ページと直接編集するページの違いを理解した。
- [ ] メニュー・フッターは `partials/` を編集し、`npm run generate` で反映することを確認した。
- [ ] 原本、`dist/` の公開用コピー、本番サイトを区別できる。
- [ ] [セキュリティ設定](../deployment/SECURITY.md)の本番側未実施事項を担当者と確認した。
- [ ] 公開・障害対応の承認者と、バックアップからの復旧手順を確認した。
- [ ] 本番確認を実施した日・結果を、下の作業記録に残した。

## 5. 作業記録の書式

以下をコピーして追記します。秘密情報・問い合わせ本文・個人情報は記載しません。

```text
作業日：
作業者：
依頼内容・承認者：
変更した原本：
実行したチェックと結果：
目視確認したページ・端末：
Gitコミット（保存できた場合）：
本番反映：未実施／実施（日時・担当者）
バックアップの管理番号・安全な保管先：
本番での確認結果：
残った事項・次の担当者：
```
