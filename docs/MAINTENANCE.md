# 更新手順とファイル早見表

[最初のページに戻る](../README.md)

## 1. 用語はこれだけ

| 用語 | このサイトでの意味 |
| --- | --- |
| 原本 | 編集してGitに保存するファイル。プロジェクト直下のHTMLや `partials/`、`data/` など |
| 共通部品 | 全ページに繰り返し表示するメニュー・フッター。`partials/` のファイルを編集する |
| 生成 | 原本の共通部品やデータを、ブラウザーで表示できるHTMLへ反映する作業 |
| ローカル | 自分のPC内。ここでの修正は、アップロードするまで本番には反映されない |
| 公開用コピー | `npm run build` で作る `dist/public-日時/` の中身。原本ではない |

## 2. 変更箇所の早見表

| 変更したい場所 | 編集する原本 | 注意 |
| --- | --- | --- |
| ホームの見出し・本文・事業カード | `index.html` | 画像を変える場合は下の画像手順も確認 |
| 各サービスの本文 | 対応するHTML（下の一覧） | `<header>` と `<footer>` は共通部品から再生成されるので直接編集しない |
| 全ページのメニュー | `partials/header.html` | `{{HOME_CURRENT}}` と `{{BUSINESS_HREF}}` は自動置換の印なので消さない |
| 全ページ下部の会社案内・リンク | `partials/footer.html` | 会社名・住所・電話は本文にもあるので全体検索する |
| 色・文字サイズ・余白・角丸 | `style.css` | まず先頭の `:root` にある共通設定を確認。個別の見た目は該当クラスを検索 |
| 問い合わせフォームの見た目 | `contact.css` | 送信処理は変更しない |
| 実績・メーカー・図面表の見た目 | `reference.css` | 生成HTMLを直接直さない |
| メニュー開閉・スライダー・アニメーション | `main.js` | 変更後は全ページとスマートフォン表示を確認 |
| 問い合わせ画面の案内文 | `contact.html` | 受付時間、メール、電話は先方の承認が必要 |
| 送信先・送信元・認証設定 | サーバー外部設定。設定項目の例は `deployment/contact-config.example.php` | 本物のパスワードを原本へ書かない。管理者向け作業 |
| 納入先・メーカー・スクリーン仕様 | `data/reference-content.json` | [専用手順](../data/README.md)を参照 |
| 図面PDF・DXFのZIP | `downloads/visual-master/` と上記JSON | 承認された資料だけを使う。旧URLの維持・転送も確認 |
| ページ名・公開対象の一覧 | `data/site-pages.json` | 新ページの追加はセキュリティ設定も関係するため経験者と実施 |

## 4. 文章を直す例

1. 対象ページをブラウザーで確認し、上の表でファイルを選びます。
2. エディターで現在表示されている文章を検索します。HTMLのタグ（`<h2>` や `</p>` など）を残し、文章だけを修正します。
3. `npm run generate`、`npm run check` を実行し、`npm run preview` で確認します。
4. タイトルやページの説明も変わる場合、`<title>`、`meta name="description"`、`og:title`、`og:description`、JSON-LDの内容も一致させます。判断が難しければ経験者へ依頼してください。
5. 実際に掲載内容を更新したページだけ、`sitemap.xml` の該当URLの `lastmod` を更新日（YYYY-MM-DD）にします。点検だけで全ページの日付を進めないでください。

会社の住所・電話・受付時間などは複数箇所にあります。VS Codeの全体検索（Ctrl+Shift+F）で旧表記を探し、本文・フッター・検索向けデータを確認してください。`dist/` は検索対象から除きます。

## 5. 画像・ロゴを変える例

1. 権利・掲載内容を確認した画像を `images/` に追加します。日本語や空白を避けた名前（例 `meeting-room-20261106.jpg`）にすると管理しやすくなります。
2. 対象HTMLの `src="images/..."`、または `background-image: url('images/...')` を変更します。生成ページはJSONの `image` または生成スクリプトの該当設定を変更します。
3. 画像の説明である `alt` も実際の画像に合わせます。イメージ画像を実際の社内・施工実績と受け取られる表現にしないでください。
4. `npm run generate` → `npm run check` → プレビューで、PC・狭い画面の切り抜き方を確認します。
5. 不要に見える画像を一括削除しないでください。公開用コピーには参照している画像だけが自動で入ります。

ロゴは `images/bex-logo.jpg` を参照します。同名で置き換えた場合も `npm run generate` により更新番号が自動で変わります。
CSS・JavaScriptも同様で、`?v=...` の番号を21ページ手作業で直す必要はありません。
テキストの改行コードの違いだけでは更新番号は変わりません。`.gitattributes` でGit上の改行も揃えています。
ロゴの縦横比やファイル形式を変える場合は、共通部品の参照・レイアウトも確認してください。ファビコンは各HTMLの `rel="icon"` / `apple-touch-icon` 等を確認します。

## 6. コマンドの早見表

| コマンド | 何をする？ | 原本を書き換える？ |
| --- | --- | --- |
| `npm run generate` | 6ページを生成し、21ページの共通部品と更新番号を同期 | はい。対象HTMLとサイトマップのみ |
| `npm run check` | 再生成漏れ・リンク・資料・安全設定・管理手順の不整合を検査 | いいえ。検査用サーバーが一時的に自分のPC内だけで起動する |
| `npm run preview` | 自分のPCで表示確認。実メール送信は不可 | いいえ |
| `npm run build` | 自動チェック後、新しい公開用フォルダを作成 | `dist/` の新規フォルダだけ。既存原本・過去の公開用コピーは変更しない |
| `npm run test:layout` | Chromeで画面幅・操作・CSPの検査 | 原本は変更しない。別途テスト環境設定が必要 |
| `npm run test:contact` | ローカルTLS SMTPで送信処理を検査 | 原本は変更しない。本番メールは送らない。別途PHP等の設定が必要 |

後半2つは経験者向けです。必要な環境変数は各スクリプト冒頭と `deployment/SECURITY.md` を確認してください。
`npm run check` の成功だけでは実機Safari・本番メール・Apache/nginxの設定適用は確認できません。

## 7. エラーが出たら

| 表示・症状 | 対応 |
| --- | --- |
| 「再生成が必要です」 | `npm run generate` の後、もう一度 `npm run check` |
| JSONの構文エラー | 直前に編集したJSONのカンマ・引用符・括弧を確認。ファイル全体を作り直さない |
| missing target / Missing document | 表示されたファイル名の綴り・画像や図面の保存場所を確認 |
| Non-public reference | 公開対象外のファイルにリンクしている。制限を外す前に、参照先が本当に公開してよいか確認 |
| 生成済みHTMLを直接直してしまった | 変更内容を控え、JSONまたは生成スクリプトへ移す。退避前に再生成しない |
| CSSや画像が古いまま | 保存 → `npm run generate` → 再読み込み。本番なら更新したHTMLと画像/CSSの両方が配置されたか確認 |
| プレビューでフォームが送れない | 正常です。送信機能はPHP対応の検証環境で確認する |
| 本番が500エラーになった | 作業を止め、公開前の設定・ファイルへ戻す。`.htaccess` を無条件に削除せず管理者に連絡 |

原因が分からない場合は「実行したコマンド」「表示されたエラー」「編集したファイル」「本番を変更したか」を担当者へ伝えます。パスワードや問い合わせ内容は添付しないでください。
